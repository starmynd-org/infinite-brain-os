# Agent Load Order: doctrine-example

This file is navigational. It tells agents what to load next after reading
`core-doctrine.md`, by query class.

## Always load first

`core-doctrine.md` in full. It is the compressed synthesis. Do not skip it to go
directly to pillars or concepts.

## By query class

**Foundational claim** (what is the core first principle):
Load `pillars/example-discipline-pillar.md`.

**Definitions and models** (what does a term mean, what is the framework):
Load the relevant file in `concepts/`.

**Past decisions** (why was this direction chosen over another):
Load the relevant file in `decisions/`.

**How to apply** (step-by-step procedure or repeatable pattern):
Load the relevant file in `playbooks/`.

**What is unsettled** (open questions, contradictions, contested readings):
Load files in `synthesis/`.

**Source context** (where did this come from, what was the migration path):
Load files in `support/`.

## What not to load first

Do not load `concepts/` or `decisions/` before `core-doctrine.md`. Those files assume
the canonical framing. An agent that skips canon and goes directly to a concept may
apply the concept without its foundational constraints.

## Navigational note

This file does not carry node frontmatter. It is a navigational aid for agents, not
a knowledge node.
