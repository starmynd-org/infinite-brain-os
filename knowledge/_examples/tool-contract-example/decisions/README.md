# Decisions: tool-contract-example

This folder holds records of design decisions about this integration.

## What goes here

A decision node records why the integration was built in a specific way. Typical
content: why a specific auth mechanism was chosen, why certain operations are excluded
from the contract, why a particular error-handling strategy was adopted.

These are decisions about the namespace itself (how the contract is documented and what
it covers), not decisions about the upstream API design.

## What does not go here

Operational details go in `operations/`. Cross-cutting constraints go in
`canon/core-contract.md`.

## This example scaffold

This folder is empty in the example scaffold. Add decision nodes as the namespace matures
and non-obvious integration choices accumulate.
