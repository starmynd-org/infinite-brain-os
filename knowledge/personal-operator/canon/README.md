# personal-operator canon

This folder holds the compressed, operator-approved, provenance-bearing first-principles of the
`personal-operator` namespace. Canon is the first thing an agent loads, and it routes to the deeper
nodes. It does not paraphrase the pillars node by node; it compresses across them.

## Files

- `core-doctrine.md`: the keystone synthesis. Read it whole first. It states what this namespace is
  (the durable operator model), who consumes it (the chief-of-staff department), what lives here versus
  in the runtime and data layers, and the skeleton-now posture.
- `agent-load-order.md`: the load-order controller. Tells you what to read next by query class.

## What canon means here

Canon is operator-approved. An agent drafts at `verified_by: operator-pending`; the operator signs off. The
canon never invents the operator's personal values: the operator profile's structure is canonical, but its
operator-specific values are set by the operator as logged decisions, not by an agent.

This namespace carries `canon_posture: full`. It holds durable operator doctrine, not live state, so it
carries no `current-truth.md`. Live queue state, raw time data, and secrets stay out of canon per the
surface boundary.
